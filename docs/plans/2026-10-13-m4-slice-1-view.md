# Mission 4, slice 1 (per-side knowledge in the engine) Implementation Plan

> **For agentic workers:** implement this plan task by task with the
> **implement-spec** skill. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The engine, not a host, decides what each side may see:
`cna-game::view` gives a side's view of the state and of a batch of
events under 3.61 (limited intelligence), with enemy supply units under
stable aliases; the data embedding moves to `cna-embed` so a server can
share it; `preview` stops leaking dice. Hot-seat behaviour is unchanged.

**Spec:** `docs/designs/2026-10-13-multiplayer-server-design.md`
**Depends on:** `origin/main` with Mission 3 complete (`cec9776`).

## Rules for every task

- Stage only your own files (`git add <paths>`, never `git add -A`).
- Paste the output of each verification command into the PR body.
- `export CARGO_TARGET_DIR=$HOME/.cache/cna-engine-target`; a gate that
  fails on data this tree does not have is re-run before being believed.
- No hash pinned by Mission 2 or 3 moves in this slice: the state, the
  log and replay are untouched; only what is *shown* changes.

### Task 1: `cna-embed`

- [ ] New crate `crates/cna-embed` (lib): move `crates/cna-web/build.rs`
  and `crates/cna-web/src/embedded.rs` into it unchanged in behaviour

- [ ] `cna-web` depends on it and re-exports nothing it did not export
  before; `wasm-pack test --node crates/cna-web` and the web e2e still
  pass. Commit `embed: the data embedding as its own crate`.

### Task 2: `Aliases`

- [ ] Write the failing tests in `cna-game::view::aliases`:
  `Aliases::new(&GameState)` maps every supply piece (real and dummy) of
  each side to `supply:<side>:s<k>`, `k` from 1 in an order drawn from a
  `ChaCha` stream seeded by the game's seed and a fixed domain tag (not
  the game's `rng`, which must not advance); `alias` and `unalias` are
  inverse; the mapping is equal after `to_json`/`from_json`; a non-supply
  id passes through both unchanged; an alias that names no piece is an
  error on `unalias`.
- [ ] Implement. The seed is `GameRng`'s (`rng.seed()`, saved with
  `draws`); seed a separate `ChaCha8Rng` from it and the domain tag, so
  the aliases are fixed for the game and the game's dice never move.
  The seed itself stays server-only (the spec's *Seeds*), so the
  permutation cannot be recomputed by a client.
- [ ] `Aliases::unalias_order(Order) -> Result<Order>` rewrites every
  `PieceId` an order can carry (exhaustive `match` on `Order`, no `_`
  arm). Test with a `barrage` whose `target` is an aliased supply unit.
  Commit.

### Task 3: `view_for`

- [ ] Write the failing tests (one per row of the spec's knowledge
  table), on the golden game's state after set-up and after order 70
  (mid-combat): for `viewer = Some(Axis)`, own pieces keep every field;
  Commonwealth pieces keep only the counter-face fields, real and dummy
  supply both `kind: supply-unit` under aliases, with the removed fields
  absent (not null); sealed answers of the other side are absent until
  the reveal event; `log`, `rng` and anything holding the seed are
  absent; `to_act`, `assaults_to_resolve` and the label fields
  (`unit_type`, `name`, `abbreviation`) are present. With `open = true`
  the enemy keeps every field (still no `log`/`rng`, sealed answers
  still hidden). `viewer = None` (a spectator, not exposed yet) sees
  both sides as an enemy.
- [ ] Move `cna-web::api::Game::view`'s body into

  `view_for(state, data, state.to_act(), true)`; its tests
  (`a_sealed_answer_is_redacted_from_the_other_side_s_view_until_revealed`,
  `view_adds_unit_type_per_piece`, …) pass unchanged.
- [ ] Places that might leak and must be checked by reading: `combat`

  List each in the PR with what was done. Commit.

### Task 4: `events_for`

- [ ] Classify all 38 `Event` variants in a table in the module doc:
  *public* (both sides see it as is), *own* (only the side it concerns),
  or *reduced* (the enemy gets a reduced form). Ground each *reduced*
  row in cna's 3.61 table (`rules/95-abstract-logistics-and-air.md`,
  *Limited intelligence*) and the combat restatement; where the prose
  does not settle a field, take the stricter reading and add a bullet to
  the PR's "requests for cna" list.
- [ ] Write the failing tests: one per variant, own vs enemy, built from
  the golden game's events where the variant occurs and by hand where it
  does not; aliases applied to every `PieceId` in an enemy's events.
- [ ] Implement `events_for(state, events, viewer, open) -> Vec<Value>`
  with an exhaustive `match` (no `_` arm). An *own* event is dropped for
  the enemy, not replaced. Commit.
