# Mission 4, slice 1 (per-side knowledge in the engine) Implementation Plan

> **For agentic workers:** implement this plan task by task with the
> **implement-spec** skill. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The engine, not a host, decides what each side may see:
`cna-game::view` gives a side's view of the state, of a batch of events
and of a refusal under 3.61 (limited intelligence), with enemy supply
units under stable aliases; the data embedding moves to `cna-embed` so a
server can share it; `preview` stops leaking dice. Hot-seat behaviour is
unchanged.

**Spec:** `docs/designs/2026-10-13-multiplayer-server-design.md`
**Depends on:** `origin/main` with Mission 3 complete (`cec9776`).

## Rules for every task

- Stage only your own files (`git add <paths>`, never `git add -A`).
- Paste the output of each verification command into the PR body.
- `export CARGO_TARGET_DIR=$HOME/.cache/cna-engine-target`; a gate that
  fails on data this tree does not have is re-run before being believed.
- No hash pinned by Mission 2 or 3 changes value in this slice: the
  state, the log and replay are untouched; only what is *shown* changes.

### Task 2: `Aliases`

- [ ] Write the failing tests in `cna-game::view::aliases`:
  `Aliases::new(&GameState, key: [u8; 32])` maps every supply piece
  (real and dummy) of each side to `supply:<side>:s<k>`, `k` from 1 in
  an order drawn from a `ChaCha8Rng` seeded by `key`, a per-game secret
  the host keeps (never the game's seed or `rng`; the game's dice must
  not move). `alias(viewer, id)` aliases only the enemy's ids;
  `unalias(viewer, id)` maps only the enemy's aliases back; a side's own
  real ids pass through both (the golden game posts
  `supply:axis:dummy-1` as the Axis). The two are inverse; the mapping
  is equal after `to_json`/`from_json`; a non-supply id passes through;
  an alias naming no piece is an error on `unalias`.
- [ ] Implement. Hot-seat (`cna-web`) never aliases (`open = true`) and
  passes an all-zero key.
- [ ] `Aliases::unalias_order(viewer, Order) -> Result<Order>` rewrites
  every `PieceId` an order can carry (exhaustive `match` on `Order`, no
  `_` arm). Test with a `barrage` whose `target` is an aliased enemy
  supply unit. Commit.

### Task 4: `events_for`

- [ ] Implement `events_for(state, aliases, events, viewer, open) ->
