# Mission 3, slice 2 (wasm facade) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task by task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A `cna-web` crate that puts a whole Graziani game behind a
small JSON API callable from JavaScript, built by `wasm-pack`.

**Architecture:** `crates/cna-web` (`crate-type = ["cdylib", "rlib"]`)
depends on `cna-data`, `cna-game`, `wasm-bindgen`, `serde-wasm-bindgen`.
Static data is embedded with `include_str!` from `vendor/cna/data`, parsed
once into the data handle `apply` takes. No logic beyond translation.

**Spec:** `docs/designs/2026-10-13-minimal-ui-design.md`
**Previous plans:** slice 1.

## Interfaces

```rust
#[wasm_bindgen] pub struct Game { state: GameState }
#[wasm_bindgen] impl Game {
    pub fn new_game(scenario: &str, seed: u64) -> Result<Game, JsError>;
    pub fn load(json: &str) -> Result<Game, JsError>;   // checks rules_commit
    pub fn save(&self) -> String;                        // GameState JSON
    pub fn view(&self) -> JsValue;     // clock, weather, initiative, acting player, pieces with location and display data, pending, over/report
    pub fn apply(&mut self, player: &str, order_json: &str) -> JsValue; // {ok: Event[]} | {illegal: {case, reason}}
    pub fn reachable(&self, pieces: JsValue) -> JsValue; // Reach[] | {illegal}
    pub fn placements(&self, unit: &str) -> JsValue;     // HexId[]
    pub fn answers(&self) -> JsValue;                    // Order[]
    pub fn log(&self) -> JsValue;                        // accepted orders
}
#[wasm_bindgen] pub fn geometry() -> JsValue; // hexes {id, terrain, settlement, coastal, points}, hexsides {a, b, features, p0, p1}, places {name, hex, x, y}, bounds
```

`view`'s piece entries carry what the counter needs and the UI cannot
compute: `unit_id, side, nation, id_code, name, unit_type, equivalent,
toe, cpa, cp_spent, cohesion, morale, location, reserve`.

## Tasks

1. **Crate and embedding.** Add `crates/cna-web` to the workspace; a
   `data.rs` with one `include_str!` per file Graziani loads and a
   `static DATA: OnceLock<Data>`. Native test: the embedded data equals the
   data loaded from disk. Commit `cna-web crate with embedded data`.
2. **Game class.** Implement the methods; each one is a native-testable
   Rust function returning `serde_json::Value`, wrapped by a thin
   `#[wasm_bindgen]` method. Native tests: new game has pending set-up;
   a legal `Place` returns events; an illegal one returns
   `{"illegal":{"case":"59.2",…}}` and `save()` is unchanged; `load(save())`
   round-trips byte for byte; a save with another `rules_commit` errors.
   Commit `Game API`.
3. **geometry().** Built from slice 1's `geom`; test every hex has six
   points and the bounds contain them. Commit `Map geometry export`.
4. **wasm tests.** `wasm-bindgen-test` (node) repeating the new/apply/
   save/load test through JS values; `wasm-pack test --node
   crates/cna-web`. Record the release `.wasm` size (gzip) in the PR
   body; above 5 MB gzip, add `wasm-opt -Oz` (wasm-pack does by default
   in release) and say so.
5. **CI.** Install `wasm-pack` (pinned version via the official installer
   action or `cargo install --locked`), run the wasm tests. Commit
   `CI: wasm tests`.
