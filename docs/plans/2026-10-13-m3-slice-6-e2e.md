## Rules for every task

- Stage only your own files (`git add <paths>`, never `git add -A`).
- Paste the output of each verification command into the PR body; do not
  summarise it as "passes".
- Stop any dev or preview server you start (`npm run dev`, `npm run

- On any visual change, capture the slice's proving screenshot and run

  paste its verdict in the PR.

## Tasks

1. **Save.** Button downloads `graziani-gt<N>-os<M>.json` (`save()`).
   Commit `web: save`.
2. **Load.** File input; a `load` error (wrong `rules_commit`,
   malformed) is shown and the current game kept. Commit `web: load`.
3. **Autosave.** `save()` to `localStorage` after each accepted order;
   on start, "Continue" if present, else "New game" with a seed field
   (random default, shown). Commit `web: autosave`.
4. **The golden game.** A driver maps each `LoggedOrder` of
   `graziani-short.json` to the clicks that produce it (tray + hex,
   stack + reachable hex, panel inputs, buttons) and asserts after each
   that the DOM's counters match `__cna.view()`. Midway: save, reload the
   page, load the file, continue. End: `__cna.save()` byte-equal to
   `cna-play replay` of the same log. An order the driver cannot express
   by clicks is a failing test, not a skipped one. Commit `web: e2e
   golden game`.
5. **Docs.** README: running the UI (`cd web && npm ci && npm run wasm &&
   npm run dev`, toolchain), nothing hosted, the secrecy limits;
   `NOT_SIMULATED.md`: the UI enforces nothing itself; the design's
   Status; `AUTOPILOT.md` queue; `MISSION 3 COMPLETE` in the journal and
   `PROGRESS.md`.
