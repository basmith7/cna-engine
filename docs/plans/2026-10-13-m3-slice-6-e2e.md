# Mission 3, slice 6 (save, load and the end-to-end game) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task by task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Save and load, an autosave, a full scripted game through the
UI in CI, and Mission 3's docs.

**Spec:** `docs/designs/2026-10-13-minimal-ui-design.md`
**Previous plans:** slices 1–5.

## Tasks

1. **Save.** A "Save" button downloads `graziani-gt<N>-os<M>.json`
   (`engine.save()`). Commit `web: save`.
2. **Load.** "Load" accepts a JSON file; an error from `Game.load`
   (wrong `rules_commit`, malformed) is shown and the current game kept.
   Commit `web: load`.
3. **Autosave.** After each accepted order write `save()` to
   `localStorage`; on start offer "Continue" when one exists, else "New
   game" with a seed field (default random, shown so a game can be
   reproduced). Commit `web: autosave`.
4. **The scripted game.** Playwright drives M2's
   `tests/games/graziani-short.json` order by order through UI clicks
   (a small driver maps each `Order` to the clicks that produce it), then
   asserts the UI's `save()` equals the state `cna-play replay` gives for
   the same log, byte for byte. Midway, save, reload the page, load the
   file, and continue. Commit `web: e2e golden game`.
5. **Docs.** README: how to run the UI (`rustup target add
   wasm32-unknown-unknown`, `cargo install wasm-pack`, `cd web && npm ci &&
   npm run wasm && npm run dev`) and that nothing is hosted;
   `NOT_SIMULATED.md`: no rule change, a note that the UI enforces
   nothing itself; the design's Status; `AUTOPILOT.md` queue (Mission 3
   `done`); `MISSION 3 COMPLETE` in the journal and `PROGRESS.md`.
